lock Certificado / Conexão

Informe os atributos da conexão. O inspetor aplica as mesmas checagens de um navegador — sem abrir conexão real.

lightbulbO endereço que a pessoa digitou. Ex.: seubanco.com.br.
lightbulbO nome para o qual o certificado foi emitido. Teste o ataque: ponha um nome DIFERENTE do de cima e veja a falha. Curinga: *.exemplo.com.
lightbulbQuantos dias faltam para vencer. Ex.: 60 (válido), 10 (vence em breve), -3 (expirado há 3 dias).
checklist As 5 checagens que um navegador faz
  1. Nome (SAN): o host acessado tem de estar no certificado — senão é o erro de nome divergente que um MITM provocaria.
  2. Validade: dentro do período notBefore…notAfter; expirado é recusado.
  3. Cadeia: a assinatura sobe até uma CA raiz confiável; autoassinado não sobe.
  4. Protocolo: TLS 1.3 ideal, 1.2 aceitável; 1.0/1.1/SSL são obsoletos.
  5. Cipher: AEAD (GCM/CHACHA20) forte; CBC atenção; RC4/3DES/NULL quebrados.

lightbulb O veredito geral é o pior estado entre as cinco — uma falha recusa a conexão, como no navegador.
